# whatsapp-mauve

A personal WhatsApp archive: a backup taken from your phone (Android, crypt15) after it is decrypted, live sync of new messages through a linked device, and a WhatsApp-Web-style viewer on `127.0.0.1`. Each WhatsApp account has its own folder, and everything runs inside Docker.

> First time? Start with [HOW-IT-WORKS.md](HOW-IT-WORKS.md): a plain-language explanation of how the project works.

## Layout

```
whatsapp-mauve/
  README.md          this file (how to use it)
  HOW-IT-WORKS.md    plain-language guide for beginners
  compose.yml        generated by `wa regen`: includes one file per account (do not edit)
  wa                 the control command for everything (entry point)
  install.sh         the installer (wa + image build + new account + start)
  wa.conf.example    settings template (every key is documented in it)
  profiles/          data: one folder per account (database + media + session). Do not touch
  state/handoff/     development notes
  src/               all project code (see src/README.md)
    Dockerfile, .dockerignore, Makefile
    docker/          container entry point + systemd alert units
    tools/           the code itself (server, sync, importers, UI, tests)
    docs/            ARCHITECTURE.md (architecture and details)
  legacy/            the old install without Docker (not maintained)
```

## Installation

Requirements: `docker` (with `docker compose`) and `python3`.

    git clone <repo> whatsapp-mauve && cd whatsapp-mauve
    ./install.sh          # guided setup: installs `wa`, pulls the image (builds it locally if it cannot be pulled), adds an account and starts it

The wizard explains the 64-digit key. Get the key from WhatsApp: **Settings > Chats > Chat backup > End-to-end encrypted backup > Use 64-digit encryption key instead**. If you lose the key: turn encryption off and on again to get a new key, then make a new backup (old backups will not open with the new key).

## Running

    docker compose up -d                    # all accounts (the image is built if missing)
    docker compose up -d <name>-sync        # sync for one account
    docker compose up -d <name>-viewer      # viewer for one account
    docker compose logs -f <name>-sync      # follow the log
    docker compose down                     # stop everything

Services: `<name>-sync` (live sync, starts at boot) and `<name>-viewer` (the viewer on the port set in `wa.conf`; it starts on demand unless `WA_VIEWER_AUTOSTART=1`).

## `wa` commands

`wa` works from anywhere (including through the link at `~/.local/bin/wa`).

    wa new <name> [--port N]                 new account in profiles/<name>/ (picks a free port automatically)
    wa list                                  accounts, ports, and run status
    wa up|down|restart|status|logs [name|all]  without a name = all accounts
    wa key <name>                            save the 64-digit key (.wa_key, mode 600, never printed)
    wa import <name> [phone WhatsApp folder]   decrypt msgstore + media
    wa link <name>                           link as a linked device (QR), optional
    wa pin <name> [--clear]                  viewer lock PIN
    wa backup <name> <dest>                  full copy of the account without cache/
    wa restore <account folder> [--move]     restore the account into profiles/ and start it
    wa regen                                 regenerate compose.yml for all accounts
    wa notify-on|notify-off <name>           desktop notification if the link breaks
    wa migrate-legacy <old folder> <name> [--dry-run]   migrate the old install (without docker)
    wa update [name]                         install the newest release (see Releases and updates)
    wa autoupdate-on|autoupdate-off [name]   one-click update from the viewer (+ optional nightly update)
    wa build | wa shell <name>

After editing `wa.conf` (port, `WA_VIEWER_AUTOSTART`, `WA_PHONE_DIR`) or after a restore on another machine, run `wa regen` (`wa up` does it automatically).

## Account folder

    profiles/<name>/
      wa.conf        account settings (port, access, password, ...)
      compose.yml    generated from wa.conf (do not edit)
      archive.db     the database (the only source of truth)
      media/         media with WhatsApp's own folder names (WhatsApp Images/, WhatsApp Voice Notes/, ...)
      state/         WhatsApp session (auth/), the key, and internal settings
      user/          profile pictures, bookmarks, and user data
      cache/         regenerated as needed; not included in backups
      .wa_key        encryption key (mode 600)

You can copy `media/` to your phone or open it with any program. The account that has a `wa.conf` is the account: `profiles/` is the registry, and nothing is kept in `~/.config`.

## Backup and restore

    wa backup myname /mnt/backup         # creates /mnt/backup/myname (the database through sqlite backup, hardlinks preserved)
    wa restore /mnt/backup/myname        # on any machine with docker and install.sh (copies into profiles/, then wa regen)

The backup includes the session (`state/auth`), the encryption key (`.wa_key`), and all messages: store it somewhere private. Do not run a restored copy while the original is running on the same session at the same time.

## Linking `media/` with Immich

An external read-only library. Add this under `immich-server` in Immich's `docker-compose.yml`:

    volumes:
      - /path/to/whatsapp-mauve/profiles/<name>/media:/usr/src/app/external/whatsapp-<name>:ro

And in Immich: *Administration > External Libraries > Create*, with Import path = `/usr/src/app/external/whatsapp-<name>`, and Exclusion patterns = `**/.Statuses/**` if you do not want statuses.

## Releases and updates

Every release is a multi-arch (amd64, arm64) image on GitHub Container Registry: `ghcr.io/3mro777o/whatsapp-mauve` (tags `1.0.1`, `1.0`, `latest`). By default the account compose files use `ghcr.io/3mro777o/whatsapp-mauve:latest`.

- **Image mode (default):** `wa update` = `docker compose pull` + `up -d`.
- **Developer mode:** set `WA_IMAGE=whatsapp-mauve:local` in `profiles/<name>/wa.conf`. The compose file keeps `build: ../../src`, and `wa update` = `git pull --ff-only` + `docker compose build` + `up -d`.
- **Update notice:** the viewer asks GitHub for the latest release at most every 12 hours (`WA_UPDATE_CHECK=0` turns it off) and shows a banner "new version vX.Y.Z" with *What's new* and *Update now*. *Update now* needs a PIN; the container only writes `state/update-request` (it has no docker access). Run `wa autoupdate-on` once on the host: a systemd user path unit sees the file and runs `wa update` (log: `journalctl --user -u 'wa-update@*'`). `WA_AUTO_UPDATE=1` in `wa.conf` (then `wa autoupdate-on` again) adds a nightly `wa update`; `wa autoupdate-off` removes both.

Cutting a release (maintainer): edit `src/VERSION` (e.g. `1.0.1`), commit, then

    git tag v1.0.1 && git push --tags

GitHub Actions (`.github/workflows/docker.yml`) builds and pushes the image and creates the GitHub Release. The tag must equal `src/VERSION`. After the first push, make the package public once: GitHub > your profile > Packages > whatsapp-mauve > Package settings > Change visibility > Public (otherwise `docker pull` needs a login).

## Changing the code and rebuilding

The code is in the image (`src/`), so after any change:

    docker compose build && docker compose up -d

For details (code map, tests, where config keys are documented) see [src/README.md](src/README.md). For the architecture see [src/docs/ARCHITECTURE.md](src/docs/ARCHITECTURE.md).

## legacy/

The old direct install on the machine without Docker (`legacy/setup.sh`, and systemd templates). It is not maintained and is kept for reference only. Docker is the recommended way to run this.
